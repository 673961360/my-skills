# 周报/月报 Skill 设计文档

**日期**: 2026-05-26
**状态**: 设计中

## 问题陈述

需要一个自动化 skill，从多个数据源（git 提交、svn 提交、Claude Code 工作会话、企微手工总结）采集原始数据，智能归纳为工作汇报风格的周报/月报，输出为本地 Markdown 文件，可选导入为飞书/企微在线文档。

## 设计决策

### 1. 实现方式：纯 SKILL.md 指令式

- 不引入外部脚本，所有逻辑在 SKILL.md 中通过指令引导 Claude 执行
- Claude 通过 Bash 工具调用 git/svn 命令，读取 session 日志，处理用户粘贴的企微内容
- 与你现有 skill 架构一致（如 `follow-ai-coding-builders`）

### 2. 报告风格：项目分组 + 成果导向

- 按项目/工作域分组（如"C端交易系统"、"柜台债"、"IT基础设施"）
- 每条为成果导向的陈述句（"完成 XX，支持 YY"），而非过程数据（"提交 5 次"）
- 编号列表式，中文顿号编号（1、2、3、），每条以分号或句号结尾
- 适合直接粘贴到企微/飞书

### 3. 仓库配置：SKILL.md 内嵌

- git/svn 仓库路径列表直接写在 SKILL.md 的配置区
- 每个仓库路径绑定一个中文项目名称（用于报告分组标题）
- 修改仓库时直接编辑 SKILL.md

### 4. 企微数据来源：手动粘贴

- 运行 skill 时，Claude 等待用户粘贴企微总结内容
- 粘贴内容与其他数据源一起参与归纳

### 5. 下周计划：自动生成初稿

- Claude 基于本周各项目的进展，自动推断下周合理的延续方向
- 生成初稿后由用户手动调整

## 数据源详细设计

### Git 仓库

配置格式（SKILL.md 内嵌）：
```
仓库: D:\代码\my-trading-system → 项目名: "C端交易系统"
仓库: D:\代码\bond-counter → 项目名: "柜台债"
仓库: D:\代码\my-skills → 项目名: "IT基础设施"
```

采集命令：
```bash
git log --after="YYYY-MM-DD" --before="YYYY-MM-DD" --author="你的用户名" --pretty=format:"%H|%ai|%s"
```

### SVN 仓库

配置格式同 Git。

采集命令：
```bash
svn log -r {YYYY-MM-DD}:{YYYY-MM-DD} --username "你的用户名"
```

### Claude Code Session

数据源：`~/.claude/` 下的 session 日志文件
- 读取目标时间段内的会话文件
- 提取会话主题（从第一条 prompt 概括）
- 统计修改文件数、使用 skills

### 企微总结

- 用户手动粘贴到对话中
- Claude 将其中的条目解析为成果陈述

## 分组与命名规则

1. **配置映射**：每个仓库路径在 SKILL.md 中绑定了中文项目名
2. **自动归组**：commit/session 按所属仓库归入对应项目分组
3. **跨项目条目**：如果 commit 涉及多个项目（如同时改了 my-skills 和另一个仓库），按文件变更比例归入主导项目
4. **未配置仓库**：git/svn 扫描结果中不属于任何已配置仓库的，归入"其他"分组
5. **空分组**：某项目本周无动静的，不显示该分组标题

## 成果归纳规则

1. **从 commit message 提取实质**：不只是复述 message，而是从 diff 内容判断做了什么（如"feat: add login" → "完成登录模块开发"）
2. **合并同类项**：同一项目下的多个小 commit 合并为一条成果（如 5 个提交都在修同一个 bug → "修复 XX 问题"）
3. **成果句式**：每条以"完成/完善/修复/优化/推进/沉淀/补齐/协同"等动词开头，以具体成果结尾
4. **重要性排序**：同项目内按重要性从高到低排列，而非时间顺序
5. **剔除噪音**：merge commit、格式调整、依赖升级等不单独列为成果，除非改动影响重大

## 下周计划生成规则

1. **延续性**：本周"完成开发"→ 下周"测试上线"；本周"调研分析"→ 下周"提炼规范"；本周"部署接入"→ 下周"能力验证"
2. **参考历史**：如果上周的"下周计划"在本周变成了"本周进度"，说明延续性推断有效
3. **保守推断**：不编造项目中不存在的功能方向，只基于本周实际工作内容推断自然延续
4. **标注为初稿**：下周计划区域顶部加一行灰色注释 `<!-- 以下为自动生成初稿，请根据实际情况调整 -->`

## 输出与交付

1. **本地保存**：生成到 `reports/YYYY-MM-DD-weekly.md`（周报）或 `reports/YYYY-MM-monthly.md`（月报）
2. **终端输出**：同时在终端打印报告全文，方便快速预览
3. **可选导入**：询问是否通过 `lark-doc` skill 创建飞书在线文档
4. **企微总结复用**：打印时提醒用户可直接复制粘贴到企微

## 人工审核流程

生成初稿后进入审核环节，Claude 在终端打印完整报告，然后：

1. **询问遗漏**：打印报告后询问"报告是否有遗漏或需要调整的地方？你可以直接补充条目，或告诉我修改哪一条"
2. **口头补充**：用户口述新增条目（如"再加一条：完成了生产环境证书更新"），Claude 归入对应项目分组
3. **修改已有条目**：用户说"第2条改成..."或"删掉柜台债那条"，Claude 实时更新
4. **调整下周计划**：用户对自动生成的下周计划进行修改或补充
5. **循环确认**：每次修改后展示更新后的相关部分，继续询问直到用户说"可以了"/"确认"/"保存"
6. **保存终稿**：确认后将审核后的完整版本保存到本地文件

**审核交互原则**：
- 初稿展示时同时显示行号或编号，方便用户引用（如"改第3条"）
- 用户回复"没问题"、"就这样"、"确认"等肯定语时直接进入保存环节
- 不要每次修改后都重复打印整份报告，只展示修改涉及的部分
- 审核环节最多 3 轮，超过 3 轮后提醒用户"你可以稍后在生成的文件中手动编辑"

## 错误处理

1. **仓库不存在**：跳过该仓库，末尾汇总中列出"未找到：/path/to/repo"
2. **无 git/svn 权限**：跳过，不报错阻断
3. **无 session 日志**：跳过 CC 分析，不影响其他数据源
4. **企微内容为空**：不强制要求，无企微内容时正常生成
