# 文档维护约定

> 5 份迭代 md 的维护元约定。写这些 md 前先读。

## 文件角色

| 文件 | 角色 | 装什么 |
|------|------|--------|
| `state.md` | 当前快照 | 进度/待办/阻塞（每轮改；goal 完成后重置） |
| `template-contract.md` | 目标规格 | 栏目/命名/顺序/验收（不含当前进度） |
| `rules.md` | 稳定经验 | 操作/口径/配置/踩坑（少改） |
| `findings.md` | 字段字典+活跃缺口 | 查表参考；缺口解决后清除 |
| `goal.md` | 目标+协议 | 北极星/边界/迭代协议（几乎不改） |

> findings=查表参考，rules=操作/踩坑经验，按"参考 vs 经验"区分。

## 不变量

- **R1 单一归属**：同一结论同一时刻只存一份
- **R2 稳定升级**：研究中→已验证时迁到更持久文件（findings→rules；过程→state）
- **R3 角色不混**：写前对照上表自检

## 收尾收敛（/goal 第 9 步逐条执行）

- [ ] 去重：同一结论在两份 md？→ 留一份
- [ ] 升级：findings 有已验证结论？→ 迁 rules 并删
- [ ] 剥离过程：contract 有"当前/待/已渲染"？→ 移 state
- [ ] 重置快照：state 有已完成产物/历史日志？→ 精简

## 机制演进

本约定随实践修正：遇"遵守反更糟/反复判不准"记为摩擦点；小修（描述/checklist/措辞）AI 直接改并记下方演进记录，大改（角色/不变量/文件增减）停下问用户；无摩擦证据不得改。
