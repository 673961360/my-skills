# 文档维护约定

> 5 份迭代 md 的维护元约定。写这些 md 前先读。

## 文件角色

| 文件 | 角色 | 装什么 |
|------|------|--------|
| `state.md` | 当前快照 | 进度/待办/阻塞（每轮改；goal 完成后重置） |
| `template-contract.md` | 目标规格 | 栏目/命名/顺序/验收（不含当前进度） |
| `rules.md` | 稳定经验 | 操作/口径/配置/踩坑（少改） |
| `findings.md` | 字段字典+活跃缺口 | 查表参考；缺口解决后清除 |
| `goal.md` | 业务目标 | 北极星/业务边界/完成口径（几乎不改） |

> findings=查表参考，rules=操作/踩坑经验，按"参考 vs 经验"区分。

## 不变量

- **R1 单一归属**：同一结论同一时刻只存一份
- **R2 稳定升级**：研究中→已验证时迁到更持久文件（findings→rules；过程→state）
- **R3 角色不混**：写前对照上表自检

## 收尾收敛（/goal 第 9 步逐条执行）

- [ ] 去重：同一结论在两份 md？→ 留一份
- [ ] 升级：findings 有已验证结论？→ 迁 rules 并删
- [ ] 剥离过程：contract 有"当前/待/已渲染"？→ 移 state
- [ ] 重置快照：state 有已完成产物/历史日志？→ 精简

## /goal 执行约定

每次执行 `/goal` 时：

1. 先读 `goal.md`、`template-contract.md`、`state.md`。
2. 涉及字段映射、数据源、API、数据库、脚本运行时，再读 `findings.md` 或 `rules.md`。
3. 按一个可验证进展单元推进：完成一个栏目内容质量、接入一个数据源、形成一个预测方法等。
4. 实施后检查证据；市场分析或预测的证据必须覆盖内容质量、数据来源和方法论，不只看标题顺序或截图。
5. 更新 `state.md`，只记录当前状态、阻塞和下一步。
6. 收尾时按上方 checklist 去重、升级、剥离过程、重置快照。

防误判规则：

- 生成命令成功、截图存在、测试通过，只能证明对应检查项通过，不能自动推出 goal 完成。
- 某栏目只有占位、样例文案或机械摘录时，最多为“已渲染”或“已映射”，不得标为“已验证”。
- 市场分析应输出业务读者可直接阅读的成段研判，不得只列关键词、计数或原始消息样本。
- 市场预测必须说明预测对象、预测指标、方法论、数据来源和不可用时的降级原因。
- 预测或分析需要外部数据源时，确定来源后必须记录到 `findings.md`。
- `/goal` 验证日报时以 `template-contract.md` 的文字规格为准（栏目顺序、版式要点、视觉检查清单），**不重新解析 `reference/目前交易日报某日输出.jpg`**；仅当文字规格与产出出现系统性偏差、或需重新校准版式时才查图，避免每次迭代重复消耗图像 token。

## 机制演进

本约定随实践修正：遇"遵守反更糟/反复判不准"记为摩擦点；小修（描述/checklist/措辞）AI 直接改并记下方演进记录，大改（角色/不变量/文件增减）停下问用户；无摩擦证据不得改。
