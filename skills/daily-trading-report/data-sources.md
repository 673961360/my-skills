## 这份报告的数据,从哪来

先把心智模型建立起来——日报里所有数据,本质来自四个地方:

1. **内部交易系统(O32 + AI Gateway)** — 我们自己的交易。指令、头寸、应急回购。**最准、可审计**,是报告的主体(01 交易、02 交收、风险提示)。
2. **外部市场行情(公开网页抓取)** — 银行间回购利率、国债收益率曲线、A 股指数。市场公开数据,实时抓,**可能抓取失败**(非关键,失败就降级)。
3. **机构市场日评(Oracle QT 聊天流,下称"QT")** — 收盘后券商/银行发的研究日评(资金面、现券)。不是我们的数据,是**市场分析的原料**,脚本整段引用,Claude 再精炼。
4. **人工 / AI 补的** — 权益评述、现券/资金文字精炼。脚本只出骨架,Claude 在生成日报时补。

### 数据流向:哪些板块共用哪些源

QT 日评和 OMO(央行公开市场操作,Open Market Operations)数据被多个板块共用,理解这个关系能避免重复阅读:

```
内部交易系统 ──→ 01 交易汇总
                02 交收汇总
                风险提示

外部市场行情 ──→ 04 OMO 表
                03 预测表(回购利率、国债曲线、A 股指数)
                权益 · 指数表

QT 日评 ─────→ 04 资金面状况(资金日评)
                现券市场分析(现券日评)
                一级市场分析(资金日评的【一级简评】小节)
                03 预测表(资金/现券情绪打分)

Claude 注入 ──→ 现券/资金/一级文字精炼
                权益评述(WebSearch)
```

> **关键**:**03 预测表不是独立数据源**,它融合 04 的 OMO 数据和 QT 日评情绪。读 03 前建议先了解 04 和 QT 的来源。

**一条关键分界**:数值和表格由脚本确定性产出(可重复、可审计);**判断性文字**有一部分是 Claude 在脚本跑完后注入的。所以同一栏里,数字可信度 ≠ 文字可信度——见文末「脚本产出 vs 人工注入」。

## 各板块数据说明(按报告顺序)

### 01 交易数据汇总

我们当天的交易。每笔 O32 指令按「买/卖」×「业务品种」分成**现券、资金、权益、一级**四类,分别统计金额和笔数;另有一张交易笔数图(按方向)。

几个口径要注意:同一笔指令改过多次的,**只算最后一次修改**(否则重复计入已撤销/改写的旧版);已撤销的指令不计;产品名/代码出报告前脱敏。回购还细到「只统计银行间市场」「融资回购=正回购、融券回购=逆回购」——这些口径在 `rules.md`。

> 📍 **代码**:`aggregate_trade_overview` / `aggregate_trade_count_by_hour` / `aggregate_trade_amount_by_direction`(`data_collector.py`),原料 `collect_trade_instructions` → 接口 `cat_sql_trade_0019`。

### 02 交收数据汇总

「16 点 30 本该到账却还没到账」的应急正回购。从实时询价系统把当天的正回购拉出来,**只留 16:30 之后才下达指令的那些**(临收盘才补的、说明头寸没平),按时间排成一张表;产品名脱敏,金额换算成万元,附一句「X 点 X 分未到账」的应急原因。

接口服务端**不支持按日期过滤**,脚本是把近 2000 条拉回来再在客户端二次筛(当天 + 16 点 30 后)。

> 📍 **代码**:`collect_emergency_repo`(接口 `cat_api_trade_0008`)→ `aggregate_emergency_repo`。

### 03 市场预测汇总

「明天资金/现券/权益/一级会怎么走」的预测表。

> 📎 **数据依赖**:本表的 OMO 净投放、政府债缴款来自 04 的资金事件日历;资金/现券情绪打分来自 QT 日评(同 04 资金面、现券分析的原料)。读本节时若对数据来源有疑问,可先翻阅 04。

> ⚠️ **这不是量化预测模型,不是专业投研结论,仅供内部快速参考。** 实际市场预测需要宏观经济分析、政策研判、流动性推演、供需结构、国际联动等大量专业判断,远非几张打分表能覆盖。本表产出仅供"方向感"参考,**不得作为交易决策依据**。

**整体逻辑** = 多路信号打分 → 阈值判方向(上行/下行/持平) → 当前值 ± 固定步长外推点位。

#### 每行生成规则

| 行 | 趋势 | 点位 |
|----|------|------|
| **资金面判断** | 扫描所有 QT 资金日评去重篇,关键词判 `不松/均衡/偏松`,**悲观优先**(任一篇"不松"→整体"不松") | `\`(定性栏无点位) |
| **10Y 国债收益率** | `bond_score` 累加(见下) → ≥1.0 上行 / ≤−1.0 下行 / 否则持平 | 当前值 ± 0.01(1bp) |
| **上证指数 / 创业板** | 当日涨跌幅 >0 上行 / <0 下行 / =0 持平(**纯当日动量**) | 当前值 ± 当前值×0.2% |
| **1Y 大行 CD 发行** | 从一级短评文本抽第一个 0.5~5 区间的数作利率,趋势固定"持平" | 当前值 |
| **1Y 大行 CD 二级利差** | 文本含"正/走阔/利差"→"正",否则"暂无判断" | `\` |

#### `bond_score` 累加打分

| 信号 | 条件 | 得分 |
|------|------|------|
| QT 现券情绪 | 含"收益率上行/走弱/卖方/OFR" | +1.0 |
| | 含"收益率下行/走强/买方/BID" | −1.0 |
| 10Y 国债收盘收益率 | ≥2.2% / ≤1.8% | +0.5 / −0.5 |
| 资金面打分折半并入 | `clamp(funding_score/2, −1, 1)` | ±1.0 封顶 |

#### `funding_score` 资金面综合打分

既影响资金面判断行,也折半并入 `bond_score`:

| 信号 | 条件 | 得分 |
|------|------|------|
| R001/DR001 利率 | ≥2.0% / ≤1.5% | +1 / −1 |
| R007/DR007 利率 | ≥2.2% / ≤1.7% | +1 / −1 |
| 当日波幅 | 高 − 低 ≥ 0.3% | +0.5 |
| OMO 净投放 | >0(投放) / <0(回笼) | −1 / +1 |
| 政府债缴款 | >0(抽水) / <0 | +1 / −0.5 |
| QT 资金面情绪 | 不松 / 偏松 | +1 / −1 |

> 📍 **代码**:`build_market_forecast` + 辅助函数 `_trend_from_score`/`_forecast_point`/`_funding_condition`/`_fmt_point`;融合 `cat_sql_trade_0012`(回购行情)、`cat_sql_trade_0013`(OMO)、QT 短评、外部行情(国债曲线/指数)。

### 04 资金市场分析

两块:央行公开市场操作(OMO)表 + 资金面状况表。

**OMO 表**来自资金事件日历——央行当天做了多少逆回购/MLF、到期多少、净投放多少,一目了然。⚠️ `STAT_DT` 是 UTC 时间戳(如 `2026-06-21T16:00:00+0000`),加 8 小时才转成北京时间,所以 **UTC 日期部分 = 北京业务日期 − 1 天**——查北京 6/22 的 OMO,代码要拿 `6/22 − 1 = 6/21` 去缓存里匹配。

**资金面状况** — ⚠️ **不是行情 API 数值,是 QT 机构日评的文字摘录**(定性,非定量)。加工流程:

1. **原料**:`fetch_daily_commentary` 从 Oracle QT 按 `CONTENT LIKE '%日评/早评/午评%'` 召回,按原文去重,标题含"资金/货币市场/存单"归为资金类。
2. **分句 + 时段分桶**:按 `。；!\n` 拆句,5 个固定桶(`早盘/OMO后/午前/午后/尾盘`);遇到时段关键词切换当前桶,**后续无时标的句子继承上一时标**(状态机)。句子必须含资金词(`资金面/隔夜/7D/14D/跨月/成交/融出/利率`等)才入桶。
3. **每桶抽 4 列**:
   - 隔夜/7 天/14 天跨月:在桶内找含期限关键词的句子,从关键词处截取,到下一个其他期限词前截断,压缩到 ≤42 字(例:`隔夜 ofr 1.5%+10bp 融出充足`)。
   - 市场状态:关键词优先级判定 `偏紧 > 偏松 > 收敛 > 均衡 > —`。
4. **入行门槛**:4 列中至少 2 列非 `—` 才保留该行。
5. **降级**:有效时段 < 2 个 → 表格不渲染,把 QT 原文打上 `<!-- 中间态 -->` 标记作 `raw_text` 输出,由 Claude 按 `funding-commentary.md` 精炼成文字短评;≥ 2 个时段则渲染表格,`overall/summary` 仍留空由 Claude 注入综合判断。
6. **附加**:`sentiment_index` 正则抽 `今日全天的资金面情绪指数[:：] 52-54-52-52` 格式,条件展示。

> 📍 **代码**:OMO = `aggregate_money_market`(接口 `cat_sql_trade_0013`);资金面 = `build_funding_market_status` + 辅助函数 `_split_commentary_sentences`/`_period_from_sentence`/`_rate_fragment`/`_market_status_from_text`/`_extract_sentiment_index`(原料 `fetch_daily_commentary`,Oracle QT)。

### 现券市场分析

机构写的利率债日评。脚本从 QT 聊天流里挑出当天最长最全的那篇现券日评,**整段原文**放进报告(只去 URL 和空行,不改文字),作为「原料」。

⚠️ **脚本出的是原料,不是成品**。生成日报时 Claude 会按 `prompts/bond-commentary.md` 把原文精炼成 3-5 句研判,并剔除和别的栏重复的部分(OMO、资金面 Shibor、一级中标——这些资金栏/一级栏已有)。**如果你看到的产出还是大段原文照搬,说明精炼步骤漏了。**

> 📍 **代码**:`generate_market_commentary`(`data_collector.py`),原料 `fetch_daily_commentary`(Oracle QT 表 `ats.t_repo_robot_chatmessage`)。

### 权益市场分析

分两块,来源完全不同:

**指数表** — 脚本从新浪(主)/腾讯(备)实时抓的上证、深证、创业板、科创50 点位和涨跌幅。这部分**确定、可信**。

**评述文字** — 脚本**不产出**(交易系统没有 A 股评述),留「外部短评暂未获取」占位。生成日报时 Claude 用 WebSearch 查当日 A 股收盘(限定东方财富/证券时报等中文财经站),补成交额、领涨板块、驱动因素。所以**评述是 AI 查的、可能滞后,指数表才是准的**。查不到当日时降级标注,不拿旧闻冒充。

> 📍 **代码**:指数 = `collect_equity_indices`(`external_market.py`);评述 = `build_equity_market_analysis`(占位),注入靠 `prompts/stock-commentary.md`。

### 一级市场分析

当天一级市场发了多少债:三张卡片(利率债发行、地方债发行、NCD 次日预发行)+ 一张明细表(国债/政金债/地方债/NCD × 各期限发行量)。数据来自资金事件日历的「发行与到期」事件,**只取发行方向**(到期的不算);汇总行缺失时从明细倒推。当天确实没发行就显示「暂无相关数据」。NCD 卡片特殊:取**次日**预发行汇总行(更具前瞻性),用 weekday 启发式跳周末算下一交易日——遇长假或 fund_events ±3 天窗口外时取不到、卡片为空(已接受的降级)。

**发行结构分析文字研判**:QT 无独立一级日评,但一级存单评述嵌在资金日评的【一级简评】小节中。脚本从资金日评代表篇的 CONTENT 中提取【一级简评】小节(正则匹配 `【一级简评】` 到下一个 `【` 或文末),清洗后作为一级栏原文 dump 填入报告。**这是中间态**——生成日报时 Claude 按 `prompts/primary-commentary.md` 精炼为 3-5 句判断性总结(发行规模评价、品种结构特征、认购需求判断),剔除逐条报价和机器过程描述。若资金日评中无【一级简评】,则不渲染文字研判,仅展示表格。

> 📍 **代码**:`aggregate_primary_market`(接口 `cat_sql_trade_0013` 的发行方向行)→ 汇总卡+明细表;`_extract_primary_section` + `generate_market_commentary`(从资金日评提取【一级简评】)→ 文字研判原文 dump → Claude 按 `prompts/primary-commentary.md` 精炼。

### 风险提示

三条固定合规提示 + 机器规则识别的风险线索。目前两条规则:头寸 T+1 可用为负 →「头寸不足」(高);指令错误率 >10% →「指令质量」(中)。无线索时只有那三条固定提示。

> 📍 **代码**:`aggregate_risk_warnings`(原料 O32 指令 + `cat_api_trade_0002` 头寸)→ `build_risk_tips`。

## 读者该知道的关键口径

这几个点跨板块,看报告或改代码时都要懂:

- **脱敏** — 产品代码前两位换 `**`(`CJ5381`→`**5381`),产品名里「创金/合信」换 `*`,括号内容脱敏。出报告前对所有产品信息生效。
- **日期要减一天** — 资金事件日历(0013)的 `STAT_DT` 是 UTC 时间戳，加 8 小时才转成北京时间，所以 **UTC 日期部分 = 北京业务日期 − 1 天**（实测 `2026-06-21T16:00:00+0000` = 北京 6/22 的数据）。代码里用 `query_date − 1 天` 去缓存里匹配。
- **应急回购的 16 点 30 判定** — 02 板块只统计「当天 16:30 之后下达」的正回购。
- **原文是中间态** — 资金面/现券栏脚本放的是机构日评原文,Claude 生成时会精炼。产出里若还是大段原文,是精炼漏了。
- **权益评述是 AI 查的** — 不是交易系统数据;搜索引擎对当天收盘索引可能滞后,偶尔查不到当日(会标注,不编造)。
- **降级文案含义** — `暂无相关数据`=该栏无数值(非交易日/无发行);`暂无有效消息`=无 QT 日评;`外部短评暂未获取`=权益评述未注入。
- **预测表是打分外推** — 不是量化模型,方向有参考价值、点位精确度低。

## 脚本产出 vs 人工注入

> 同一栏里,数值/表格由脚本确定性产出,判断性文字可能由 Claude 在脚本跑完后注入。这是数据可信度的重要分界。

| 板块 | 脚本产出(可信) | Claude 注入(脚本运行后) |
|------|---------------|----------------------|
| 01 / 02 / 04 OMO / 风险 | 全部数值与表格 | 无 |
| 04 资金面状况 | 结构化时段表 / 原文 dump | 仅原文 dump 时按 `funding-commentary.md` 精炼 |
| 现券市场分析 | QT 原文 dump(中间态) | 按 `bond-commentary.md` 精炼;QT 无日评时 WebSearch |
| 一级市场分析 | 汇总卡 + 明细表 + 【一级简评】原文 dump | 仅原文 dump 时按 `primary-commentary.md` 精炼 |
| 权益 · 指数表 | 指数点位涨跌幅 | — |
| 权益 · 评述 | 占位「外部短评暂未获取」 | **必须** WebSearch 后按 `stock-commentary.md` 注入 |
| 03 预测表 | 数值、趋势、方法说明 | 无(数值不改写) |

> 原则(`rules.md`):数值必须代码确定性计算,AI 只做编排与文字精炼,不产出、不改写数值。
