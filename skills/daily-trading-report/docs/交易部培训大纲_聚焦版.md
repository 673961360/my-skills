# 交易部培训大纲：AI如何取数、用数，并沉淀成可复用的开发提效流程

> 版本定位：聚焦版，不追求“什么都讲到”，而是把 30 分钟集中讲透三件事：  
> 1. 交易同事如何把业务需求表达成 AI 可执行任务；  
> 2. AI 如何通过 API / CLI 取数，并把结构化数据加工成指标；  
> 3. 如何用交易日报案例，把一次性问答沉淀成可复用 Skills / Agent 流程。  
>
> 培训对象：交易部同事、交易支持同事、希望用 AI 做开发提效和业务自动化的同事。  
> 培训重点：效率、取数、用数、分析、沉淀流程。  
> 非重点：安全治理、系统权限、所有场景泛泛介绍。

---

## 0. 这次培训不讲什么

为了 30 分钟内讲透重点，本次培训主动不展开以下内容：

1. 不系统讲大模型原理；
2. 不系统讲安全治理、权限、审计；
3. 不逐个介绍所有生产系统；
4. 不泛泛罗列几十个 AI 应用场景；
5. 不把 AI 包装成“万能助手”。

本次只讲一条主线：

> **交易同事如何用 AI 把生产系统里的结构化数据，变成可复核、可修改、可沉淀的交易分析产物。**

---

## 1. 课程目标

这次培训结束后，希望交易部同事理解三件事。

### 1.1 AI 不只是聊天，而是可以调用工具

交易同事看到的是一句自然语言：

```text
帮我生成 2026 年 6 月 17 日交易日报。
```

AI 背后做的是一组任务：

```text
理解任务 → 判断需要哪些数据 → 调用 API / CLI → 加工指标 → 生成观点 → 输出日报初稿
```

### 1.2 AI 开发提效的关键不是“提示词漂亮”，而是“任务可拆、数据可取、口径可验收”

一次有效的 AI 开发提效，至少要给 AI 四类信息：

```text
目标样例：最终要长什么样
数据入口：从哪些接口 / 文件 / 系统取数
计算口径：字段怎么理解、指标怎么算
验收标准：什么结果算可用、哪里必须人工复核
```

### 1.3 交易日报只是示例，真正要沉淀的是可复用流程

不是让 AI 今天临时写一份日报，而是把流程固化成 Skills：

```text
trade-daily-report skill
= 模板识别 + 取数命令 + 指标加工 + 观点生成 + 输出格式 + 人工复核项
```

# 重点一：AI 如何取数

## 3. 为什么先讲取数

交易部同事使用 AI 提效，最容易遇到的问题不是“AI 不会写”，而是：

```text
AI 没有数据；
AI 不知道数据在哪里；
AI 不知道应该查哪张表、哪个接口；
AI 不知道字段是什么意思；
AI 不知道查出来的数据如何对应业务问题。
```

所以第一件事是把生产系统能力变成 AI 可调用的工具。

---

## 4. 从自然语言到工具调用

### 4.1 交易同事的表达

```text
帮我看一下今天交易日报怎么写。
```

这个问题对人来说很自然，但对 AI 来说还不够可执行。

AI 需要进一步拆解：

```text
日期是哪天？
日报有哪些模块？
每个模块需要哪些数据？
这些数据分别从哪里取？
取回来以后怎么算？
结果如何展示？
哪些结论需要人工确认？
```

### 4.2 AI 背后的任务拆解

以“生成 2026 年 6 月 17 日交易日报”为例：

```text
任务：生成交易日报

需要数据：
1. 指令数据：当日指令数量、状态、业务类型、方向、金额
2. 成交数据：当日成交笔数、成交金额、券种、期限、收益率
3. 持仓数据：产品维度持仓变化、券种变化、久期变化
4. 行情数据：利率、收益率曲线、估值、市场价格
5. 资讯数据：当日重要公告、主体新闻、市场新闻
6. 对手数据：报价活跃度、成交贡献、未成交报价
7. 聊天消息：投资经理意图、人工备注、交易过程信息
```

### 4.3 CLI 化后的生产系统能力

交易同事不用写命令，但需要理解 AI 背后会调用类似能力：

```bash
trade-cli orders --date 2026-06-17
trade-cli trades --date 2026-06-17
trade-cli positions --date 2026-06-17
trade-cli market --date 2026-06-17
trade-cli news --date 2026-06-17
trade-cli counterparties --date 2026-06-17
trade-cli chat-summary --date 2026-06-17
```

这类命令的价值不是“炫技术”，而是让 AI 能稳定、可重复地拿到业务数据。

## 5. 交易同事需要怎么配合 AI 取数

交易同事不需要会开发接口，但需要能说清楚三件事。

### 5.1 问题边界

不要只说：

```text
帮我分析一下交易情况。
```

更好的说法是：

```text
帮我分析 2026-06-17 交易部日报，重点看指令执行、成交金额结构、未成交原因、持仓变化和需要关注的风险点。
```

### 5.2 数据范围

需要说明：

```text
日期范围：当天 / 最近一周 / 最近一个月
业务范围：现券 / 回购 / 基金 / 一揽子
产品范围：全部产品 / 某产品 / 某产品组
输出范围：日报 / 复盘 / 异常提示 / 对手分析
```

### 5.3 验收口径

需要告诉 AI：

```text
成交金额按什么单位展示？
成交率怎么算？
未成交是否包含撤单？
对手名称是否需要脱敏？
异常的判断阈值是什么？
观点是偏简洁日报风格，还是偏复盘解释风格？
```

# 重点二：AI 如何用数，并从结构化数据生成观点

## 6. 这一部分要讲透什么

AI 不是把表格翻译成中文。

真正有用的链路是：

```text
结构化数据
→ 指标
→ 对比
→ 异常
→ 归因
→ 自然语言观点
```

交易日报、交易复盘、持仓解释，本质上都离不开这条链路。

---

## 7. 从一张表到一段观点

### 7.1 原始数据

| 日期 | 业务类型 | 指令状态 | 成交金额 |
|---|---|---|---:|
| 6月17日 | 现券买入 | 已成交 | 5000万 |
| 6月17日 | 现券卖出 | 已成交 | 8000万 |
| 6月17日 | 回购 | 已成交 | 2亿 |
| 6月17日 | 现券买入 | 未成交 | 3000万 |

如果 AI 只写：

```text
今天有现券买入、现券卖出和回购交易。
```

这个结果几乎没有业务价值。

---

### 7.2 第一步：先算指标

```text
总指令数：4笔
已成交：3笔
未成交：1笔
成交率：75%
总成交金额：3.3亿
回购成交金额：2亿，占比 60.6%
现券成交金额：1.3亿，占比 39.4%
未成交集中在现券买入方向
```

这一步回答的是：

```text
发生了什么？
规模多大？
结构如何？
有没有明显集中项？
```

---

### 7.3 第二步：再做判断

仅有指标还不够，要继续判断：

```text
成交率 75% 是高还是低？
回购占比 60.6% 是正常还是偏高？
现券买入未成交，是报价问题、流动性问题，还是目标价格问题？
今天成交金额和昨天、近 5 日均值相比有没有变化？
```

这一步回答的是：

```text
这个数字意味着什么？
是否值得关注？
需要和什么基准比较？
```

---

### 7.4 第三步：形成观点

最终输出不是数字堆砌，而是一段可读观点：

```text
今日交易执行整体较顺畅，4笔指令中3笔完成成交，成交率为75%。从金额结构看，回购业务贡献主要成交量，占比约六成，现券交易占比约四成。未成交指令集中在现券买入方向，后续可重点关注相关券种报价是否偏离目标收益率，或市场流动性是否不足。
```

这段话有三层信息：

```text
描述：今日交易执行整体较顺畅
结构：回购贡献主要成交量，现券占比较低
关注点：未成交集中在现券买入方向
```

---

## 8. 生成观点的三个核心模板

为了避免泛泛讲五六类观点，本次培训重点讲透三个模板。

---

### 8.1 模板一：总量 + 结构 + 变化

适合日报开头和交易概览。

```text
今日【指标】整体【上升/下降/平稳】，主要由【业务/产品/券种】贡献。
从结构看，【A类】占比最高，【B类】相对较低。
与【昨日/近5日均值/上周】相比，主要变化体现在【变化点】。
```

示例：

```text
今日成交金额整体较昨日上升，主要由回购业务放量贡献。从结构看，回购成交占比最高，现券成交相对平稳。与近5日均值相比，今日成交放量更多体现为资金类业务需求增加，而非现券换手显著提升。
```

---

### 8.2 模板二：异常 + 证据 + 可能原因

适合复盘和风险提示。

```text
今日【对象】出现【异常现象】。
从数据看，【证据1】、【证据2】。
可能原因包括【市场因素/报价因素/产品调仓/流动性因素】。
建议后续关注【需要跟踪的指标或事项】。
```

示例：

```text
今日部分现券买入指令未能成交。从数据看，未成交主要集中在买入方向，且目标收益率与市场成交收益率存在一定差距。可能原因包括报价条件较难达成、相关券种二级流动性不足，或市场收益率波动导致对手报价收敛。建议后续关注该类券种报价分布和估值偏离情况。
```

---

### 8.3 模板三：结果 + 归因 + 后续关注

适合市场分析和持仓解释。

```text
今日【结果】。
从归因看，主要受到【因素1】和【因素2】影响。
对组合或交易执行的影响是【影响】。
后续需要关注【指标/风险/机会】。
```

示例：

```text
今日产品持仓久期小幅下降。从归因看，主要受到长久期利率债减持和短端品种配置增加影响。对组合而言，久期下降有助于降低利率波动敏感度，但也可能压缩后续收益弹性。后续需要关注收益率曲线变化及长端资产再配置机会。
```

---

## 9. 交易同事如何让 AI 写出更像业务观点的内容

不要只给 AI：

```text
帮我写一下分析。
```

更好的方式是给 AI：

```text
请基于以下指标，生成日报风格观点：
1. 先判断整体交易是否活跃；
2. 再说明主要贡献来自哪个业务类型；
3. 然后指出异常或未成交集中点；
4. 最后给出后续关注事项；
5. 文字控制在 120 字以内，避免过度判断。
```

这类提示词的重点不是修辞，而是给 AI 明确分析顺序。

# 重点三：交易日报 Skills 实战

## 10. 为什么用交易日报讲 Skills

交易日报是一个好例子，因为它同时包含：

```text
取数：指令、成交、持仓、行情、资讯、对手、聊天消息
计算：笔数、金额、占比、变化、成交率、偏离度
展示：表格、柱状图、折线图、模块标题
观点：交易概览、资金面分析、现券分析、风险提示
复核：数据口径、异常结论、敏感表述
```

这不是一次性写作任务，而是一个可沉淀的自动化流程。

---

## 11. 从日报样例拆 Skills

### 11.1 先拆模块，不要直接让 AI 生成整张图

日报可以先拆成几个核心模块，而不是面面俱到：

```text
模块一：交易概览
模块二：指令与成交
模块三：持仓与产品变化
模块四：市场与资讯影响
模块五：风险提示与人工复核项
```

注意：  
不要一开始追求完全复刻日报样例中的所有模块。  
先让 AI 稳定生成“有数据、有观点、可复核”的核心日报，再逐步补齐视觉和细节。

---

### 11.2 每个模块固定五个问题

每个模块都按同一套结构设计：

```text
1. 这个模块需要哪些数据？
2. 数据从哪个接口 / CLI 取？
3. 需要计算哪些指标？
4. AI 应该生成什么观点？
5. 哪些结论必须人工复核？
```

示例：指令与成交模块

```text
数据：指令表、成交表
接口：orders、trades
指标：指令数、成交数、成交率、成交金额、未成交方向、业务类型占比
观点：今日执行是否顺畅，主要成交来自哪里，未成交集中在哪些方向
复核：成交率口径、撤单是否计入未成交、金额单位是否正确
```

## 12. trade-daily-report Skill 建议结构

```text
trade-daily-report/
├── README.md                 # Skill 说明，什么时候用，输入输出是什么
├── template.md               # 日报结构模板
├── data_requirements.md      # 每个模块需要的数据和字段
├── metrics_rules.md          # 指标计算口径
├── viewpoint_rules.md        # 观点生成规则和示例
├── tool_mapping.md           # 模块与 API / CLI 工具映射关系
├── review_checklist.md       # 人工复核清单
└── examples/
    ├── sample_input.json
    ├── sample_metrics.json
    └── sample_output.md
```

这部分要让交易同事理解：

> Skills 不是神秘能力，本质上就是把“怎么做一件事”写成可复用流程，让 AI 每次按同样的方法执行。

## 13. 交易日报 Skill 的一次执行流程

```text
Step 1：读取日报目标和日期
Step 2：根据模板判断需要哪些模块
Step 3：根据模块调用对应 CLI / API
Step 4：清洗字段并统一单位
Step 5：计算指标
Step 6：按观点模板生成文字
Step 7：输出日报初稿
Step 8：列出人工复核项
```

其中最关键的不是最后一步“生成文字”，而是前面三件事：

```text
取对数据
算对指标
按业务逻辑解释指标
```

## 14. 本地 Claude 后续可如何参与开发提效

交易部同事和 IT 可以用 Claude 做四类工作。

### 14.1 帮忙设计接口调用流程

```text
给 Claude：日报样例 + 现有 API 文档 + 目标输出
让 Claude：梳理每个模块需要调用哪些接口、字段和参数
```

### 14.2 帮忙写数据加工脚本

```text
给 Claude：字段样例 + 指标口径
让 Claude：生成 Python / SQL / CLI 调用脚本，用于计算成交率、金额占比、变化等指标
```

### 14.3 帮忙沉淀 Skills 文档

```text
给 Claude：人工日报样例 + 已验证口径
让 Claude：生成 template.md、metrics_rules.md、viewpoint_rules.md、review_checklist.md
```

### 14.4 帮忙生成 HTML / Markdown / 长图日报

```text
给 Claude：指标结果 + 日报模板 + 样式要求
让 Claude：生成可展示的 HTML 或 Markdown 日报初稿
```

---

## 15. 结尾：把注意力从“会不会用 AI”转到“能不能沉淀流程”

最后建议这样收尾：

> AI 提效的重点，不是每次临时问一句“帮我写日报”。  
> 真正有价值的是：把交易部高频工作拆成固定流程，让 AI 每次都能按同样的数据入口、同样的指标口径、同样的观点规则生成初稿。  
> 交易日报只是起点，未来交易复盘、持仓解释、对手分析、资讯联动，都可以用同样方法沉淀成 Skills。

最终金句：

```text
一次性问答解决一次问题；
可复用 Skills 才能持续提升效率。
```
