# Goal：参考模板交易日报持续对齐

## 总体目标

基于 O32 指令数据、QT 聊天消息和允许使用的外部短评/市场数据来源，持续迭代交易日报生成能力，直到输出的 HTML 日报在栏目结构、显示顺序、命名、缺失数据处理、视觉骨架、文案质量和市场预测能力上稳定贴近 `reference/目前交易日报某日输出.jpg`。

本 goal 不允许只用“页面能生成、栏目存在、占位正确”作为完成依据。结构正确只是中间状态；资金市场、现券市场、权益市场、一级市场和市场预测必须有可追溯数据来源、合理方法论和高质量成段文案，才能进入完成判断。

本文件是 `/goal` 迭代的稳定目标，不承载易变的详细栏目规格。具体规格放在 `template-contract.md`，可随参考图理解、数据源能力和实现结果持续调整。

## 优先级

1. 用户明确指令。
2. `goal.md` 的总体目标和边界。
3. `template-contract.md` 的当前模板合同。
4. `state.md`、`findings.md`、`rules.md` 中的已验证事实。
5. 当前代码输出。

如果当前代码输出与 `template-contract.md` 冲突，说明代码尚未完成，不要反向修改目标来适配代码。

## 迭代协议

每次执行 `/goal` 时按以下流程推进：

1. 读取 `goal.md`，确认目标和边界。
2. 读取 `template-contract.md`，确认当前版本的具体规格和验收方式。
3. 读取 `state.md`，判断最近状态、待办和阻塞。
4. 按需读取 `findings.md` 或 `rules.md`：涉及字段映射、数据源、API、数据库、脚本运行时再读。
5. 对照代码/生成报告与 `template-contract.md`，按**一个可验证进展单元**推进（如完成一个栏目内容质量、接入一个数据源、完成一个预测方法）：单元内做完所有必需改动使其可验证，不跨到下一单元。
6. 实施后必须生成或检查证据，判断是否达到“已验证”。涉及市场分析或预测时，证据必须包含内容质量、数据来源和方法论检查，不能只包含标题顺序或截图。
7. 更新 `state.md`：只记录当前状态和下一步，不记录过程废话（稳定结论归 `rules.md`）。
8. 如发现 `template-contract.md` 与参考图或数据现实不符，可更新 contract，但必须说明证据和原因。
9. 收尾收敛：按 `conventions.md` 收尾 checklist 逐条执行——去重、升级、剥离过程、重置快照。

## 进度状态

后续不得只用“已实现”描述进度，必须使用以下状态：

| 状态 | 含义 |
|------|------|
| 数据可用 | 已有数据源或明确降级文本 |
| 已映射 | 已确定数据源如何填入当前模板合同 |
| 已渲染 | HTML 中已按当前合同显示 |
| 已验证 | 生成报告后，标题抽取、视觉检查、数据填充/降级、内容质量和方法论均符合合同验收条件 |

只有“已验证”才能视为完成。

## 防草率完成规则

- 生成命令成功、截图存在、测试通过，只能证明对应检查项通过，不能自动推出 goal 完成。
- 正式报告中某栏目只有占位、样例文案或机械摘录时，该栏目最多为“已渲染”或“已映射”，不得标为“已验证”。
- 市场分析栏目必须输出能给业务读者使用的成段研判，不得只列关键词、计数、原始消息样本。
- 市场预测必须说明预测对象、预测指标、方法论、数据来源和不可用时的降级原因。
- 如果预测或分析需要外部数据源，确定来源后必须记录到 `findings.md`；未记录来源不得标为“数据可用”。

## 非目标

- 不要求业务数值与参考图完全一致。
- 不编造历史趋势、外部短评、权益行情、一级市场数据或任何真实交易信息。
- 不把当前已有网页卡片板块直接视为参考模板已完成。
- 不为追求视觉一致性破坏数据真实性和可重复生成能力。
- 不实现定时自动触发或 Windows 任务计划程序；后续作为 skill 使用时由调用平台负责触发。

## 完成条件

当以下条件同时满足时，goal 才算完成：

1. `template-contract.md` 的主模板栏目全部达到“已验证”。
2. 生成命令可稳定产出 `reports/YYYY-MM-DD-daily.html`。
3. 市场预测汇总具备当前版本要求的预测方法论、具体指标和可追溯数据来源；无法取得的数据源必须记录缺口，不能用占位冒充预测。
4. 资金市场、现券市场、权益市场、一级市场文案达到 `template-contract.md` 的内容质量标准，不只是栏目存在或样例截图。
5. 缺失数据统一使用 contract/finding 中定义的占位文本，没有编造内容。
6. `state.md` 已更新为最终快照，明确无剩余阻塞。

## 停止条件

遇到以下情况应停止并报告：

- 需要用户做新的业务口径判断，例如交易分类、权益数据源、一级市场外部数据源。
- 连续两轮无法形成可验证进展。
- 涉及生产凭证、真实资金交易、不可逆外部操作。
- 参考图规格本身存在无法从现有材料判断的歧义。

## 输出格式

每轮 `/goal` 结束时使用：

```text
Done / Evidence / Next / Continue or Stop
```
